# Settled offscreen page render-resource cleanup

The reader already releases detached canvas backing dimensions. That does not itself release PDF.js page operator lists or page-local image objects. Inspection of the pinned PDF.js 6.5.438 `PDFPageProxy` shows display rendering retains these intent states by default; `cleanup()` clears them only after its internal render tasks and operator list have settled. The upstream 6.5.438 worker `CleanupPage` handler releases that page's global-image-cache references, not document text streams.

This reader change retains render resources for the currently displayed page/spread and asks PDF.js to clean a page when it becomes offscreen and has no active reader draw lease. Each draw acquires its proxies before viewport/render work, then releases them after successful visible commit or in its failure/cancellation finally block. Overlapping draws of the same proxy are reference-counted. Cancellation requests alone never release an unsettled render. A failed new spread preserves the visible old page and its resource cache; successful replacement releases only pages no longer visible. Hidden spread pages are eligible when switching to single-page mode.

Successful draws release their leases before animation/text extraction finishes, so a slow text consumer does not unnecessarily retain obsolete rendering resources. PDF.js owns any internal deferred cleanup if `cleanup()` returns false. The reader does not poll, force cleanup, modify PDF.js internals or call whole-document cleanup. Cleanup exceptions do not replace a successful rendering result or the original render error. An already-visible proxy remains cached for zoom/re-render. Revisiting a cleaned page may require rebuilding its operator list, trading extra work on revisits for reduced offscreen resource retention.

Persisted pagehide keeps visible state for bfcache. Permanent departure closes the tracker and leaves cleanup to the existing document/loading-task destruction path; late settlements cannot issue new page cleanup. The tracker drops its active/visible references on close. PDF.js page proxies, fonts, source bytes, text cache and worker/document caches are not globally evicted by this change.

This promises cleanup requests at appropriate ownership boundaries, **not a fixed process/native/GPU memory limit or immediate physical-memory reclamation**. Existing canvas pixel caps, text-cache limits, rendering/security/loading flags and complete text/search semantics remain unchanged. There is no storage, import, hashing, rights or release change.

Local verification includes 42 resource-tracker/integrated draw checks plus all 452 prior reader checks. Controlled promises cover overlapping draws, failed spreads, delayed cancellations, visible cache preservation, hidden-page cleanup and permanent/persisted departure. Real PDF.js cleanup/revisit behavior still requires the authorized hosted synthetic browser harness. No local browser or blocked storage review is used.
