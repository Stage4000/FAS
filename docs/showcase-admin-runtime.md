# Trusted private admin runtime composition (dormant)

`ShowcaseAdminRuntime::compose($auth, $config, $enabled)` replaces hand-assembled private admin bootstrap composition. It is loaded by the dormant entry, but no bootstrap/environment setting is supplied or enabled. It reuses the already initialized current FAS AdminAuth and locked native session. It never starts sessions, issues CSRF, initializes schema, constructs AdminAuth, publishes photos, or changes accounts.

The trusted bootstrap must establish the existing admin's secure cookie/session configuration **before** session_start, initialize the current app auth using its supported bootstrap, and supply an existing server-session CSRF key. The exact configuration is database (existing canonical private SQLite path), public_roots (all served roots/aliases), max_submissions/max_photo_bytes (explicit integer budgets), consent_version/consent_text (reviewed server values), and csrf_session_key (fixed key in current native session). Unknown fields fail closed. An enabled callback must return literal true; a disabled callback returns null before touching session/account/storage. Do not populate configuration, token, actor or gate from request fields.

The factory checks current authentication before opening private storage, and constructs request/controller with the same repository and current authorization adapter. All four fixed paths match the shipped wrappers. Moderation gate rechecks enablement; repository authorization rechecks the current admin. Session-token corruption or an unauthenticated bootstrap fails generically at the buffered entry; it does not open private storage. Existing session/account errors must be resolved by the app login flow, not by creating fallback credentials or sessions here.

108 new native loopback checks cover composition, secure-session rejection, unknown configuration, explicit limits, missing/invalid CSRF, private-root/missing database rejection, no implicit database creation, disabled and truthy gates, revoked auth, fixed queue/detail/photo/moderation and stale decisions. HTTPS server state is simulated; there is no real TLS/browser or production acceptance.

Still required: actual production private bootstrap path, approved storage provisioning/limits and reviewed consent/policy values, supported existing FAS login/session integration, theme and real browser/TLS verification, exact-source hosted CI/publication approval. This file is not a production bootstrap and does not remove any release hold.
