# Local candidate: touch gesture ownership

A real handler-level regression: the published reader remembers primary-touch coordinates but not its pointer identity. A release from another pointer, including a mouse/pen or secondary touch, can therefore finish that gesture and turn the page. A second touch may also leave a swipe armed during a pinch.

The candidate records the initiating pointer ID, permits only its primary-touch release at fit zoom to finish, and cancels when a secondary touch appears anywhere in the window. Pointer cancellation, lost capture, window blur and page departure discard the pending gesture. Departure uses the existing listener, before its persisted-page return; renderer/cache teardown behavior remains unchanged. Gestures begun before the PDF is ready or completed after zoom changes do not turn pages. Normal horizontal thresholds, direction, page ownership and native scrolling remain unchanged. No preventDefault or pointer-capture intervention is added.

22 new tests execute the actual handler source with synthetic events. The exact baseline fails the cross-pointer release assertion. All 362 prior focused reader/cache/search/lifecycle tests pass, plus module syntax. These are not actual hardware touch, pinch zoom, browser event ordering or visual acceptance. Independent UI review passed 40 additional assertions and five semantic controls. Draft hosted integration adds cross-pointer and outside-stage secondary-touch events to its existing mobile case; its result must be checked separately. Hardware touch/pinch acceptance remains outstanding. No deployment or release changes. This does not touch or retry the blocked storage review.
