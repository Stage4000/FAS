# Dormant composed intake application

`handle(server, post, files, sessionRef)` requires native PHP request arrays and an exclusively locked active server session. No session_start, route activation, output or runtime configuration is performed by the class. Supply reviewed repository, quota and concurrency dependencies plus trusted consent, action, explicit form TTL/capacity, clock, enable and identity callbacks. Construction must occur in trusted private configuration; disabled handle does not invoke identity, quota, slot or session issuance operations. Constructors may validate dependencies before handle, so an outer disabled factory should return null before constructing anything when deployment is off.

GET is charged before form issuance. POST acquires a slot then charges exactly once before resolving the form or decoding. Strict request/controller gates are private to that admitted synchronous scope and invalidated in finally. Configure the slot's strict gate as an independent capacity policy, not the same quota callback (which would double-charge). Quota denials/busy slots map to generic429; operational failures to generic503. Only successful GET commits the local form bucket. POST retains retry identity but each retry is a charged attempt. Existing committed responses remain idempotent.

The caller must persist the session before emitting body; session_write_close before upload completion would violate locking. Do not accept arbitrary client identity strings; trusted identity resolution/rate policy is deployment-specific and remains mandatory. Application uses no customer fields in session or quota. This is a candidate composition, not production enablement.

Synthetic native multipart tests use actual private SQLite repository/quota and actual preprovisioned slot, including externally held slot contention, exact retries, conflict, disabled GET, no POST bucket allocation, quota exhaustion and exact charge counts. Separate real root-entrypoint acceptance is still required.
