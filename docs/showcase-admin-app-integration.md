# Existing FAS administrator bridge

ShowcaseAdminAuthorization connects the repository callback to the existing global AdminAuth instance. It loads nothing, starts no session and makes no routes on include. After trusted app bootstrap, pass `new ShowcaseAdminAuthorization($auth)` as repository authorize callback; resolve actor with `$authorization->actor()` immediately before invoking a private controller. Never read actor ID from POST. Every callback rechecks the active server session and calls AdminAuth::isLoggedIn anew; there is no cached boolean. Only existing list/review/moderate actions are admitted. Exceptions and unknown actions deny.

Reviewed app contract: Stage4000/FAS main 6993209ba92dbe77c36e3a61ba7146bf2d2db236 admin/auth.php blob f387c7c6657d247e0709951b17f5da45f160aa74. isLoggedIn rereads active account, admin role and current session token. Keep the server session lock for the request. Bootstrap/construct AdminAuth separately: its constructor initializes account schema; the adapter never does that. Do not substitute requireLogin as authorization callback, because it redirects/exits and writes analytics cookies.

Tests include 29 adapter contract assertions and nine assertions using the exact verified current app class with synthetic account/token/Timezone/security dependencies and constructor bypassed. They prove immediate rejection on disabled account, changed role/session token, deleted account, mismatched actor, and nonliteral login flag. They do not test production account store, account-token algorithm, complete app bootstrap, browser sessions or deployment. Fixture auth source is never deployed. This is one actual-app bridge; routes, private UI, CSRF/admission and production acceptance remain required.
