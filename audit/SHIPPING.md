# Direct carrier shipping migration

**Updated:** October 5, 2026
**Approved carrier scope:** USPS and UPS.  
**Current release state:** rate integration, order-selection provenance, guarded administrator label purchase and cancellation, one-attempt USPS original-label recovery, audited confirmation of carrier-verified original labels, private label storage, carrier tracking polling, transactional customer tracking notification queue, administrator tracking/email follow-ups with audited reconciliation, read-only CLI/administrator readiness reports, administrator shipping-provider/Easyship/carrier settings and PayPal capture checks implemented and retested locally with mocks. Carrier actions and customer tracking emails have not been enabled or verified on deployment; Easyship remains the configured default. Client onboarding instructions have already been sent; credentials are pending.

- [x] USPS OAuth v3/domestic pricing and UPS OAuth/Rating adapters, with the existing checkout rate contract.
- [x] Deployment-owned configuration separate from ordinary settings saves; Easyship, direct-with-fallback and direct-only modes.
- [x] Per-carrier activation gates prevent sandbox/unverified credentials from supplying public quotes.
- [x] New PayPal and Apple Pay orders recheck a saved quote against the current provider mode and carrier activation; quotes from before a cutover, rollback or carrier shutdown must be recalculated. Existing payment-attempt recovery remains available; checkout clears a stale selection and prompts a fresh rate calculation. Retested locally with synthetic orders and client mocks.
- [x] Measured individual parcels with carrier-compatible edge ordering, bounded quantities, domestic scope and per-product origin checks. Incomplete dimensions and mixed/unavailable origins cannot silently become direct quotes. USPS size/weight eligibility is checked across the full shipment before carrier calls or cache reuse, with service-specific limits repeated before label purchase.
- [x] Direct quotes require a unique active default warehouse for unassigned products; a read-only catalog scan reports saleable product measurement and origin gaps locally.
- [x] Administrator warehouse mutations require an active account and CSRF; selecting or replacing a default origin is atomic, while invalid selections and failed edits preserve the existing default. Locally retested with an isolated database.
- [x] Read-only administrator shipping readiness page and packed-parcel editing guidance implemented and locally retested; the page does not contact carriers or expose credentials.
- [x] Administrator USPS/UPS credential entry implemented with private, atomic file storage outside the web root, password and CSRF checks, status-only display, independent carrier removal and activation safeguards. Isolated HTTP tests pass; actual client credentials and deployed private-directory permissions remain pending.

The sidebar links to Shipping Settings, while the readiness report remains accessible from that page. General Settings saves preserve Easyship credentials. Local synthetic HTTP tests cover direct activation gates and rollback; no real carrier account was contacted.
- [x] Private cross-worker SQLite token/quote/cooldown cache, CLI initialization/health/cleanup, bounded transport and response reads.
- [x] Normalized USD totals, account-rate preference, unsupported-service filtering and no invented delivery dates.
- [x] First-party free shipping, shared endpoint rate limits and Apple Pay server-owned quote binding retained. Direct all-free and mixed carts now save a full-cart carrier estimate and parcel scope without increasing the customer shipping charge.
- [x] Local shipping, payment, security, catalog and SEO checks passed.
- [ ] Deploy matching runtime files and retest on the origin after credential and storage configuration.

Detailed phase content is retained until required deployment and carrier retests pass.
